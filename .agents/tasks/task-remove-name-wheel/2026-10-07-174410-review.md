# Delete the standalone "Name your fate" Name wheel (v1)

The standalone Name wheel room ("Name your fate", formerly Monitor 01) is removed as a duplicate of "The roster" in Players & rules. The room tile, its content page, the two-mode wheel tab switcher, and every free-wheel action and helper are deleted; players are now entered only in Players & rules. The one hard constraint was that the To Die (Round 2) sit-out draw shared the same on-screen wheel rendering through `wheelMode==='round2'`, so the change relocates that draw to a dedicated non-navigable screen key `sitout` rather than deleting the wheel screen outright. The engine is left untouched so old backups carrying a populated `wheel` object still validate and load at schema v4.

Watch for: the zoom-back close animation degrades silently when the sit-out screen is the active screen because no matching room tile exists (confirmed, cosmetic); one dead `.entry-editor` CSS rule survives (confirmed, cosmetic). No functional regressions found.

**Verdict**: APPROVED

## High-level view

The deletion is clean. The `wheel` tab is gone from the `tabs` array and the `renderRoom()` tile config, the room numbering renumbers 01-05 to close the gap, and `render()` dispatches `tab==='sitout'` to `sitoutWheelPage()` instead of routing a shared `wheel` screen through `wheelMode`. Every free-wheel-only identifier (`wheelPage`, `wheelModeTabs`, `spinWheel`, `randomIndex`, `wheelNames`, `wheelMode`, `wheelLast`, and the `spin`/`wheel-*`/`*-winner`/`data-wheel-mode` actions) is removed, and the initial `tab` default moves from `'wheel'` to `'settings'`. No dangling reference to any deleted symbol remains in `static/app.js`.

The To Die sit-out draw keeps working. It now lives on a screen key (`sitout`) that is deliberately absent from `tabs`, so it never appears in `#nav` or the `#monitors` grid, yet it is still reachable: the To Die `r2-wheel` action calls `openScreen('sitout')`, and `progressRound2()` sets `tab='sitout'` before animating the next pair. The retained drawing path (`sitoutWheelPage`, `sitoutCandidates`, `animateSitoutPair`, `drawWheel`, the `#wheel-canvas`, and the `wheelAngle`/`spinning`/`sitoutBusy`/`sitoutAnimating` globals) is intact, and the breadcrumb is special-cased to "MONITOR 03 / TO DIE" so the removed tab index does not corrupt the label.

Backward compatibility is preserved by not touching `engine.py`: `new_state()` still seeds the inert `wheel:{text:'',remove_winner:false}` block, `validate()` still defaults and validates it, and the client `reset-all` literal still writes a valid wheel object. Old backups with a populated wheel survive load.

The known gaps are cosmetic only: the close-screen zoom-back animation finds no `[data-open="sitout"]` tile and skips the animation (the dialog still closes correctly), and a single `.entry-editor` CSS rule for the deleted entry list lingers unused.

### Sit-out draw relocation to a non-navigable `sitout` screen

Two spots that previously keyed off the `wheel` tab index needed handling, and both were. The breadcrumb computes `tab==='sitout'?'BH / MONITOR 03 / TO DIE':...`, avoiding a `tabs.findIndex` of `-1` that would otherwise render "MONITOR 00". The post-render canvas draw guard changed from `if(tab==='wheel')` to `if(tab==='sitout')drawWheel(sitoutCandidates().map(p=>state.names[p]))`, so the canvas is drawn only on the sit-out screen and always with the sit-out candidate list — the free-wheel branch that formerly fed `wheelNames()` is gone.

### Close-screen zoom-back when the active screen is `sitout`

`closeScreen()` resolves its zoom target with `document.querySelector('[data-open="${lastMonitor}"]')`. `lastMonitor` is assigned in `openScreen()` only when the dialog is not already open, and the sit-out screen is always reached with the dialog already open (via `r2-wheel` from the To Die screen, or via `progressRound2()` which mutates `tab` directly), so `lastMonitor` stays `'round2'` and the close animation flies back to the To Die tile in the normal flow.

The residual gap is narrow: if the dialog were ever closed while `lastMonitor` were `'sitout'`, the selector returns null, the zoom-back animation is skipped, and `target?.focus()` is a no-op. In practice `lastMonitor` is never `'sitout'`, so this is latent rather than live, and the dialog still closes with state saved — the only loss is the visual zoom-back. (confirmed, cosmetic)

### No dangling identifiers after deletion

A full scan of `static/app.js` finds no surviving reference to `wheelPage`, `wheelModeTabs`, `spinWheel`, `randomIndex`, `wheelNames`, `wheelMode`, `wheelLast`, or the removed `spin`/`wheel-clear`/`wheel-roster`/`wheel-shuffle`/`remove-winner`/`roster-winner`/`data-wheel-mode` click actions. `node --check static/app.js` passes. `drawWheel` kept its signature but its default argument changed from `names=wheelNames()` to `names=[]`, which is correct now that its only caller passes the sit-out candidate names explicitly. `resetWheelResult()` was trimmed to just `wheelAngle=0` (the `wheelLast=null` line was dropped with the global); it is still invoked after backup restore and in `reset-all`, both harmless since the sit-out angle is the only remaining wheel state.

### Backward-compatible backup loading

`engine.py` is unchanged (confirmed via `git diff` — zero lines), so `new_state()`/`validate()` keep the `wheel` block at schema v4 with no migration. The one UI-side risk was the `reset-all` literal: it still writes `wheel:{text:'',remove_winner:false}`, so a client reset produces engine-valid state rather than tripping `validate()`. The field is now pure inert ballast — surfaced nowhere in the UI, carried only so old backups load.

### Test coverage

The Python suite adds `Rules.test_removed_name_wheel_backward_compat`, which asserts a fresh state carries the inert wheel default at v4, a populated legacy wheel survives a JSON round-trip plus `validate()` plus `evaluate()` without being stripped or rejected, and a backup missing the `wheel` key entirely still validates with the default block. That covers both the presence and absence paths of the compatibility contract.

The UI harness moved the sit-out assertions off `wheelMode==='round2'` onto `tab==='sitout'`, and added negative assertions that would fail if the Name wheel were still navigable: no `tabs` entry keyed `wheel` or labelled `Name wheel`, no `data-open="wheel"` tile and no "Name your fate" art in the rendered `#monitors`, and — looping every navigable tab's renderer — no "Name your fate" screen and no `data-wheel-mode` markup. It also asserts `typeof` is `undefined` for `wheelPage`, `spinWheel`, `wheelModeTabs`, `randomIndex`, `wheelMode`, and `wheelLast`, which pins the deletion of each symbol. Both suites run green (45 Python tests OK, UI harness exit 0), and the orchestrator confirmed test meaningfulness by reversion.

Not tested: the close-screen zoom-back behavior from the sit-out screen (the cosmetic animation gap above) is not exercised, but that is a visual-only path with no state impact.

### Bundled copy and style changes

The diff also renumbers room eyebrows and monitor labels (01-05 instead of 01-06), updates the `settings`/`overview` monitor titles, trims the "wheel" mention out of the legacy-archive notice copy, and updates the HTML meta description and README to drop the Name wheel. These are all direct consequences of the removal, not unrelated churn. One leftover: `static/style.css` still contains `.entry-editor{padding:15px}` for the deleted entry list — dead but harmless. (confirmed, cosmetic)
