# Ambient background nukes and a stickman "into the furnace" elimination cutscene (v1)

Frontend-only change (static/index.html, static/app.js, static/style.css; README + task metadata) adding two Doomsday-themed effects over the existing world SVG. First, an ambient blast loop spawns a nuke or explosion at a random 1–5s cadence with a camera shake confined to a new `#world-shake` wrapper inside `#world`, gated by the Pause-world toggle and `prefers-reduced-motion`. Second, a skippable cartoon furnace cutscene plays before the end-of-round standings for each of the three rounds, throwing labelled stickmen of that round's eliminated players (round1/round2 `CUT`, final `rank>3`) into a furnace. engine.py/app.py are untouched and the schema stays v4. Both test suites pass (44 Python OK, node UI exit 0) and the live probe serves `/`, `/app.js`, `/style.css` at 200.

Watch for: the ambient blast loop keeps spawning nodes and shaking `#world-shake` while a room/result dialog is open, since gating only checks reduced-motion and Pause-world, not whether a modal is up (possible — cosmetic only, blasts sit behind the backdrop). Everything else — trigger gating, per-stage names, podium sparing, skip/Esc, reduced-motion fallback, shake confinement — checks out against the requirements.

**Verdict**: APPROVED

## High-level view

The shake is isolated correctly. A new `#world-shake` wrapper sits inside `#world` and wraps only the scene SVG and the dynamically-spawned `#world-blasts` layer; `.world-shade` and `.observation-frame` stay outside it, and `<main>`/`#content`/`#screen-dialog`/`#result-dialog` live entirely outside `#world`. The shake transform (both the WAAPI `shakeWorld()` and the CSS `world-quake` keyframes) only ever targets that wrapper, so data entry and the dialogs never move — requirement 4 is satisfied structurally, not just by convention.

The ambient loop is a self-rescheduling `setTimeout` picking a delay in `[1000,5000]ms`, appending a blast node and removing it on `animationend` with a timer fallback, so there is no unbounded DOM growth. It is gated by `blastGated() = reducedMotion() || worldPaused()`, wired into the Pause-world toggle (pause stops, resume restarts only when motion is allowed), and suppressed during the cutscene via a shared `cutsceneActive` guard plus a hard `stopWorldBlasts()`.

The cutscene triggers exactly where the spec requires: inside `openMatchResult`, only when `resultFinal && v.complete` and the eliminated list is non-empty. Because `complete` is `ready and not tied` in the engine for all three stages, an unresolved tie falls through to the normal "EXTRA GAMES NEEDED" fullscreen with no cutscene, and non-final submits still open the cumulative popup. Eliminated names come straight from the engine view — `CUT` rows for round1/round2, `rank>3` for the final — so the podium top-3 are spared.

Dismissal routes through a single `endCutscene()` shared by the Skip button, click-anywhere, Esc (capture-phase so it beats the dialogs' own cancel handlers), and natural completion; it clears timers, removes the keydown listener so focus is never trapped, and resolves the promise so `openMatchResult` proceeds to focus the result dialog's close button. Under reduced motion the animated toss is replaced by a static `ELIMINATED: names` caption that still honors every dismiss path.

### Trigger gating across the three rounds

The hook lives inside `openMatchResult(key,match)` right after `resultFinal` is computed:

```js
resultFinal=(match===meta.count-1)&&v.games.every(g=>g.ready);
if(resultFinal&&v.complete){
 const names=eliminatedNames(key);
 if(names.length)await playCutscene(names);
}
```

`v.complete` is the engine's `ready and not tied` for round1, round2, and final alike (engine.py lines 338, 383, 454), so the cutscene fires only on the settled final match of each stage. An unresolved tie leaves `complete` false and the code falls through untouched to the existing `resultFullscreen` tie/extra-game path — the node test confirms the round2 tie fixture submits its last match without ever setting `cutsceneActive`, landing on "EXTRA GAMES NEEDED". A non-final match never reaches the branch (`resultFinal` false), and an empty eliminated list skips `playCutscene` so standings show directly.

`eliminatedNames(key)` reads `CUT` rows for round1/round2 and `rank>3` for the final, sorted by rank. The node assertions pin this down per stage with exact names: round1 throws exactly its two `CUT` players and no `ADVANCE` player, and the final throws exactly the `rank>3` finishers while every `rank<=3` podium name is asserted absent from the stage markup. These assertions read the real rendered `#cutscene-stage` innerHTML and the real `eliminatedNames` output, so they would fail if the trigger or the name source regressed.

### Ambient loop lifecycle and gating

`spawnBlast()` appends a `.world-blast` node (nuke variant at 50% probability, larger `--blast-size`), schedules removal on `animationend` with a `setTimeout(done, dur+400)` fallback, and triggers the CSS pop on the next frame. The fallback is also the only removal path in the vm sandbox where no real animations fire, which keeps the test honest about no DOM accumulation. The loop reschedules itself with a fresh `1000 + random*4000` delay each tick and bails via `stopWorldBlasts()` the moment `blastGated()` turns true.

Pause-world wiring is in `worldClick`: toggling to paused calls `stopWorldBlasts()`, resuming calls `startWorldBlasts()` only when `!reducedMotion()`. The node test drives the real `#world-toggle` click through the delegated handler and asserts `blastTimer` goes null on pause and non-null on resume, and that `startWorldBlasts()` is a no-op under both reduced-motion and world-paused.

One gap: `blastGated()` considers only reduced-motion and Pause-world. When a user opens a room or the result dialog, the loop keeps ticking — new blast nodes are appended and `shakeWorld()` keeps running on `#world-shake` behind the modal backdrop. The pre-existing `.inside-room`/`.page-hidden` CSS selectors that pause the SVG are never set by JS (they predate this PR), so there is no existing signal to lean on. This is cosmetic — the blasts are occluded by the dialog and the shake can't reach content — but it is wasted work during score entry. Possible improvement, not a blocker.

### Cutscene dismissal, focus, and reduced motion

`endCutscene()` is the single exit for Skip, click-anywhere, Esc, and natural completion. It clears the pending timers, removes the capture-phase `keydown` listener, hides the overlay, clears `cutsceneActive`, and resolves the promise that `openMatchResult` is awaiting — so control returns to the standard path that focuses `.result-close`. Because the listener is always torn down on exit, focus is not trapped and the `#screen-dialog`/`#result-dialog` cancel handlers keep working. The Esc handler is registered capture-phase on `document` because the overlay is a `<div>`, not a `<dialog>`, so Esc would otherwise bubble to `#result-dialog`'s cancel and dismiss the wrong layer.

Under reduced motion `buildCutscene` emits a static `ELIMINATED: name1, name2` caption (names run through `esc()`), skips the toss animation, and auto-advances after 1.8s while remaining skippable. The node test asserts the caption branch renders the names under the sandbox's `matches:true` default.

### Test coverage

The new assertions exercise real code paths rather than static markup: they submit the actual final-match click for round1 and final, drain microtasks so the `await playCutscene` is reached, then read the live overlay state (`cutsceneActive`, `overlay.hidden`, `#cutscene-stage` innerHTML, `#cutscene-caption`) and assert exact eliminated names, podium sparing, figure count, the no-trigger-on-non-final case, the tie no-trigger case, the single-dismiss path, the reduced-motion caption, and empty-list immediate resolve. Each would fail if the implementation were reverted.

Not tested: the WAAPI toss arc itself and the shake transform values (the sandbox stubs `animate`), and there is no assertion that the loop stops when a dialog opens — consistent with that behavior not being implemented.
